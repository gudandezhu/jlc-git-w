# 产品经理知识库管理规则集

本 skill 分为两层：

- **核心层**：定义产出物契约和规则标准。所有项目必须遵守，不可覆盖
- **适配层**：定义实现方式和流程参数。可通过项目 CLAUDE.md 覆盖

# 核心层

以下内容定义产出物标准和规则，适用于所有项目。

## 项目配置（可选）

在项目 CLAUDE.md 中添加以下内容覆盖默认配置：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|

| to-prd.prd-checklist | 无 | PRD质检清单文件路径。未配置则按15模块逐一自检 |

未声明的配置项使用默认值。覆盖示例见 `ref/project-claudemd.md`。

## PRD 编写规则

当用户要求编写或修改 PRD 时，自动执行以下规则。

### PRD 必填模块（15项）

每个 PRD 文档必须包含以下模块，缺一不可：

| # | 模块 | 必填 | 说明 |
|---|------|------|------|
| 1 | 基础信息 | 必填 | 版本、状态、创建日期、文档负责人、关联原型路径 |
| 2 | 项目综述 | 必填 | 业务背景（痛点+现状）、项目目标（2-3个可量化）、业务场景 |
| 3 | 核心需求概述 | 必填 | 功能定义、配置说明、约束条件 |
| 4 | 编码映射 | 按需 | 涉及系统菜单/功能模块改动时必填。生成独立文件 `menu-tree.md`（菜单树）和 `function-tree.md`（功能树），放在PRD同目录。需要配置 `encoding-source` 提供编码数据源，未配置则跳过此模块 |
| 5 | 模块关联说明 | 必填 | 与其他系统的关联（关联模块/关联内容/联动方式） |
| 6 | 业务流程图 | 必填 | Mermaid全流程图，覆盖完整业务链路（含异常分支） |
| 7 | 功能详细说明 | 必填 | 每个功能页包含：交互元素及字段定义表 + 验收点清单 |
| 8 | 权限控制 | 必填 | 功能权限、数据权限、日志记录 |
| 9 | 业务流程与防错 | 按需 | 涉及业务流程时必填 |
| 10 | 异常场景处理 | 必填 | 数据异常 + 操作异常 + 权限异常（最易遗漏，重点检查） |
| 11 | 非功能需求 | 按需 | 性能、安全、兼容性 |
| 12 | 验收标准 | 必填 | 每个验收项 = [条件] + [操作] + [预期结果] + [验证方法] |
| 13 | 版本规划 | 按需 | 分期开发时必填 |
| 14 | 待确认项 | 按需 | 有待确认问题时填写 |
| 15 | 文档信息 | 必填 | 版本号、日期、状态、修改记录 |

### PRD 编写硬性规则（7条）

1. **禁止英文表名/字段名**：PRD面向业务需求，禁止出现英文数据库表名、字段名。数据来源规则统一使用 `中文单据名称.中文字段名` 格式，如 `订单.订单状态="已完成"`
2. **禁止问号**：待确认项确认后必须转为陈述性结论，不得以疑问句形式保留
3. **禁止模糊描述**：使用具体数值和明确逻辑，不说适当、合理等模糊词
4. **异常优先**：先描述异常场景，再描述正常流程
5. **前后一致**：字段名称在整个文档中保持一致
6. **可测试**：每个功能点都有对应的验收标准
7. **编码映射必填**：涉及系统菜单或功能模块改动时，必须生成 `menu-tree.md` 和 `function-tree.md`。编码不存在时标注：`复用`（已有编码直接引用）、`新增`（全新页面，上线后补充）、`补充编码`（页面存在但功能无编码）。需要 `encoding-source` 配置，未配置则跳过

## 评审规则

当用户要求评审文档或页面时，自动执行评审。具体检查维度和评审标准由适配层定义。

### 提取AC（验收标准）

**触发**：需求评审通过后，用户说提取AC/生成验收标准/生成ac。

**流程定位**：提取AC发生在「需求评审通过」之后、「角色评审」之前。

**输出**：项目目录下的 `ac.md`（GOAL/AC/UI 三章节结构）。

**质量要求**：AC必须经过质量评审，未通过必须修复后重新评审。具体评审方法和合格标准由适配层定义。

## 运营宣发规则

当用户说生成宣发内容/运营宣发/写更新日志/写功能公告/写帮助文档/出宣发计划时触发。

### 执行流程

```
读取PRD → 功能故事提炼 → 评估功能等级(S/A/B/C) → 生成对应内容资产 → 输出宣发计划
```

### 功能等级评估（4维度，各1-5分）

| 等级 | 总分 | 必须产出 |
|------|------|----------|
| S级 | ≥16 | 故事卡+更新日志+公告+帮助文档+渠道文案+博客+销售话术+宣发计划 |
| A级 | 12-15 | 故事卡+更新日志+公告+帮助文档+渠道文案+销售话术+宣发计划 |
| B级 | 8-11 | 更新日志+公告+帮助文档+宣发计划 |
| C级 | ≤7 | 更新日志 |

内容生成风格和输出路径由适配层定义。

## PRD 模板与质检

- 如果配置了 `prd-template`，使用指定模板作为起点；否则按15模块结构直接编写
- 编写完成后自检：如果配置了 `prd-checklist` 则对照清单检查，否则按15必填模块逐一检查
- 涉及界面改动时，UI原型放在 `ui/` 目录下

## 任务管理规则

当用户要求创建或执行任务时，自动执行以下规则。

### 任务生命周期

```
创建 → 执行 → 评审 → 完成 → 归档
```

### 任务创建流程

1. 在 `工作管理/任务/` 下创建任务文件：`YYYY-MM-DD_任务名称.md`
2. 任务文件包含：任务信息表（创建日期/状态/负责人/目录）、背景、目标、范围、输入物、执行情况、输出物、评审记录
3. 状态标记：🚀进行中 / ✅已完成 / ⏸️已暂停 / ❌已取消

### 任务验收标准

- 任务目录结构符合规范
- PRD文档包含全部必填模块
- UI原型命名符合规范
- 任务记录完整

## 评审参数（默认值）

以下参数可通过配置 `review-dir` 覆盖：

| 类型 | 重点检查项 |
|------|-----------|
| C端页面 | 用户体验、视觉效果、响应式、交互体验 |
| B端系统 | 功能完整性、数据准确性、权限控制 |
| 测试评审 | 测试覆盖率、用例质量 |
| 角色分工 | 各角色评审职责 |

如果配置了 `review-dir`，优先引用该目录下的评审标准文件覆盖上述默认值。

## AC提取参数（默认值）

- **评审方法**：4专家并行评审（PRD覆盖度、可判定性、边界异常、准确性一致性）
- **合格标准**：总分 ≥95/100 且 P0问题 ≤3个
- **重审上限**：最多循环10次

## 运营宣发参数（默认值）

### 内容生成规则

1. **用户语言**：禁止技术术语，面向终端用户
2. **价值导向**：传达用户收益，不是功能描述
3. **数据支撑**：优先使用PRD中的可量化目标
4. **场景化**：从用户日常操作场景出发
5. **行动引导**：每个内容资产必须包含CTA

### 输出路径

内容资产输出到项目目录 `运营宣发/` 下。如果配置了 `promotion-template` 则按模板生成，否则按内置内容生成规则输出。

## Git 协同规则

涉及文件变更时自动遵守：

### 强制规则

1. **产出前**：`git pull` 拉取最新代码
2. **产出后**：`git add` → `git commit` (commit规范必须为 #0000开头,后续内容大于6字符)→ `git push`
3. **纯探索/问答**：不触发Git操作
4. **分支策略**：日常小任务在main分支，大型任务创建feat/分支

### 提交信息格式

```
类型: 项目前缀-问题ID 描述
```

| 类型 | 使用场景 | 示例 |
|------|----------|------|
| feat | 新增文档或功能 | `#0000 feat: PRJ-0001 新增采购入库PRD v1.0` |
| fix | 修改已有内容 | `#0000 fix: PRJ-0002 修复表单字段缺失` |
| docs | 更新知识库或规范 | `#0000 docs: PRJ-0003 更新业务知识库-权限模块` |

> 项目前缀（如 `PMKB`、`PRJ`）在项目 CLAUDE.md 中定义。

## 过程记录规则

执行任务过程中自动记录发现的异常、知识库缺失、规范不足等问题。

### 触发条件

发现以下任一情况时自动记录：
- 知识库内容缺失或过时
- 规范体系存在漏洞
- 流程设计可优化
- 工具或环境缺陷

### 存储位置

项目目录下 `过程记录/` 子目录，文件名 `YYYY-MM-DD_分类关键词-简述.md`。

### 问题记录模板

```markdown
### [序号] 问题标题

- **发现场景**：在做什么任务时发现
- **问题描述**：具体什么内容不正确/缺失/不合理
- **影响范围**：对当前任务的影响
- **建议改进**：后续应如何优化
- **分类标签**：`知识库缺失` / `知识库过时` / `规范缺失` / `规范优化` / `流程优化` / `工具缺陷`
```

### 不记录的情况

- 用户操作失误导致的临时问题
- 已知且已接受的技术限制
- 与当前任务无关的发现

## 知识库生成规则

当用户提供页面URL并要求采集/录入知识库时触发。

**触发词**：生成知识库/采集页面/录入知识库/搭建XX知识库。

**执行步骤**：

1. 读取对应区域的页面组成说明和页面索引
2. 采集页面结构信息
3. 按模板生成文档
4. 同步更新索引（链接地址记录、模块README、页面索引三处必须同步更新）

## 行为红线（每次必遵守）

1. **不修改现有文件**：除非用户明确要求
2. **先确认后执行**：复杂操作前先列出步骤大纲
3. **规范自动遵循**：执行任务时自动检索并遵循 `规范/` 下的对应规范，不依赖人工提醒
4. **记录产出**：完成任务后在任务文件中记录产出物路径
5. **提炼经验**：可复用的流程经验写入 `工作管理/教程/`
6. **中文内容禁止使用Edit工具**：Edit工具处理中文内容时会产生U+FFFD乱码。所有包含中文的文件修改必须使用Node.js `fs.writeFileSync` 完成。每次写入后必须用 `Buffer.from(content, 'utf8').includes(Buffer.from([0xEF, 0xBF, 0xBD]))` 检查是否存在乱码

## 术语约定

| 术语 | 定义 |
|------|------|
| AC | 验收标准（Acceptance Criteria） |
| CTA | 行动号召（Call To Action） |
